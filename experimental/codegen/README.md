# Startup-specialized page scans

The standalone crate compares a page-zero predicate emitted at startup with statically linked versions of the same assembly and every available A1 scanner. It generates only a fixed scan body. Runtime detection selects SSE2, AVX2, AVX-512F/BW or NEON and a group of one, two or four vectors using the data-cache line size. ERMS and FSRM affect string copies and do not select a zero-test body. The Rust caller checks the remainder. The assembler writes, relocates and seals one read/execute mapping. A host that declines this transition can still use its static or scalar scan. The explicit generated trial reports this refusal.

Use an unmodified checkout of AsmJit at `677a10bac2c24f7e068cf1f9e675bf51c7b534ea` as `ASMJIT_SOURCE`. CMake builds it only when the experimental feature is selected. No C++ runtime is added to the binary. From this directory run `cargo test --features experimental --locked`, `cargo run --features experimental --locked -- self-check`, or `cargo +nightly-2026-11-01 miri run --features experimental --locked -- self-check`. The latter exercises the scalar fallback.

The optional Measure dispatch sets `codegen_lab=true` and runs one architecture at a time. The writer creates a 256 MiB fixture with 90% zero 4 KiB pages. Each sample includes selection and generation for the generated candidate, writing and synchronization; restored contents are read and compared after timing. Fifteen pairs alternate method order. The run preserves the finalized generated bytes and SHA-256 digests. The report includes A1's pinned scalar, library, vector and all available assembly candidates, with AVX-512 where detected. One architecture's gain does not satisfy the two-architecture graduation criterion.
