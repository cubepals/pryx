# K6 validation

Built pryx up/check, idempotent credential/file/binary installation, systemd units and persistent
Postgres/RustFS storage, initial hash-only API key bootstrap, runtime asset packaging, generated
API docs, operations/architecture/quickstart docs, the composite Action, and the generated Python
SDK plus wrapper. The release workflow packages all service binaries and both SDKs with licenses.

The final isolated `bun run check` passed 218 tests across 34 files against real Postgres
(6839 assertions, no failures/skips), plus Biome, TypeScript, contract/client drift, generated API
docs and release metadata. An earlier run hit two five-second timeouts while parallel build work
was running; it is not counted as a pass. The isolated rerun kept the existing test timeouts.
Frozen install, expanded structure and actionlint passed; baseline and node formats are unchanged.

The compiled control test loaded packaged migrations/bootstrap assets, authenticated the initial
key and served join.sh over actual listeners. All three binaries compiled and printed 0.1.0;
the compiled CLI's up --check reported this host lacks root/systemd. TypeScript SDK packing and
its Node ESM entry passed. Python generation drift passed with the pinned tool; three Python
unit tests passed and the real-control test skipped visibly. Python sdist/wheel builds passed.

A local Action smoke against actual HTTP/Postgres and the node double checked CLI SHA256,
unchanged sandbox argv, absence of a host-side command marker and retained snapshot output.
Its initial fake heartbeat aged out during packaging; the repeat used an explicit fixture pulse
and passed. This is not a Docker/real-daemon Action result.

The fresh Ubuntu one-box job builds artifacts, runs up twice, runs hello and the Action with
snapshot, then Python against the real daemon. It reports its elapsed time in the job summary.
This job, full Docker e2e and release publication were not run locally; no duration or CI result
is claimed. Daemon private identity files are an explicit documented exception to the plan's
literal environment-file-only wording. All other generated installer secrets stay in 0600 unit
environments; the existing enrollment token file is deleted after enrollment.
