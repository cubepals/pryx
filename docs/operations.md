# Operating pryx

Adapted from Cubepals' fleet operations guide. The operator API owns node identity, lifecycle,
placement and history; the public API owns sandbox lifecycles. Nodes never choose assignments.

For one Linux systemd host, run `pryx up --check --domain pryx.test`, then, as root,
`pryx up --domain pryx.test`. Debian and Ubuntu install missing Docker from Docker's own repository
and nftables from apt. Other systemd Linux hosts need Docker and nftables installed first.
The installer downloads its exact release's binaries and checks SHA256SUMS before installation.
It keeps Postgres and the S3 store in persistent Docker volumes, runs control and edge as systemd
units, enrolls the local daemon and explicitly allows alpine images unless --allow-image is given.
A repeated run retains credentials, data, binaries and files already matching the desired state.
The domain is immutable until existing public address assignments are migrated deliberately.

Control, operator, node endpoint, Postgres and S3 bind to loopback in the one-box setup. Public
HTTP/TLS/raw fronts belong to edge. Add a trusted TLS reverse proxy for remote API access and DNS
for the public domain; pryx does not manage your DNS or issue sandbox TLS certificates. The
sandbox owns its TLS certificate. The API key printed once by up configures public clients:

```sh
export PRYX_API_URL=http://127.0.0.1:8082
export PRYX_API_KEY=...                 # the initial key, printed once
pryx run --image alpine:3.22 -- echo hello
```

Control/edge/operator/store/Postgres credentials generated by up are in root-owned 0600 unit
environment files under /etc/pryx. Storage containers source a read-only mount of that file;
Docker's saved container configuration contains no generated password. The daemon's existing
identity format requires private certificate keys under its root-only /var/lib/pryxd/identity
and a one-time enrollment token file, removed after enrollment. These 0600 daemon files are the
exception to the plan's environment-file-only rule; changing their format is outside this installer.
Do not copy an enrolled state directory into an image. If up stops between marking the initial
key printed and displaying it, create another with the operator API; it will not print it again.

## Adding nodes and daily operation

Join control, edge and nodes through a private network (for example WireGuard). Configure the
node endpoint's names/addresses and firewall before joining remote hosts. Only control reaches
pryxd's mutual-TLS management API; only edge reaches edge-audience ports. Images are explicitly
allowed by host policy, never by a public request. Use `pryx node token <region>` with
PRYX_OPERATOR_API and PRYX_OPERATOR_TOKEN on a trusted operator host, paste its returned join
line as root on the node, and append `--allow-image <prefix>` for each permitted image.
Use --address when the host has multiple possible private addresses. Then `pryx node ls` shows
active/healthy and placement begins. XFS reflink makes snapshots cheap until data changes;
ext4 works with full copies and needs extra disk space.

```sh
export PRYX_OPERATOR_API=http://127.0.0.1:8081
export PRYX_OPERATOR_TOKEN=...          # from the protected control environment
export PRYX_OPERATOR=operator
pryx node ls
pryx node get <node-id>
pryx node events
pryx node summary
pryx node drain <node-id>
pryx node undrain <node-id>
```

Drain stops new placement and upkeep moves assigned sandboxes when another node has room.
It can interrupt applications; schedule maintenance appropriately. With nowhere to move, data
stays on the old node. A full node refuses new work; a sleeping sandbox can move before wake
when memory elsewhere is needed. Snapshot upload must complete before the last local copy is
released. Inspect sandbox events and node issues before retrying failures.

## A host stops answering

Defaults become suspect after 15 seconds and unavailable after 45 seconds; health is measured
using database time. Inspect `pryx node get`, the provider console/network, `journalctl -u pryxd`
and `pryxd doctor`. A daemon restart leaves containers running; a host reboot resumes only after
control authorizes it. A network partition never authorizes another live copy by itself.

When the host is permanently lost, first fence it so it cannot run: power it off through a
provider that guarantees it stays off, boot rescue, or remove it from the private network and
edge's reach. Then use an operator confirmation, for example:

```sh
pryx node lost <node-id> --fenced-by power-off --reason 'disk failure'
```

The operator API accepts power-off, provider, network or none as the proof category; record the
actual action in the reason. A beating host is refused unless explicitly forced. Upkeep rebuilds
under a new epoch from the newest uploaded snapshot when capacity exists. Work after that
snapshot exists only on the lost host. With no uploaded snapshot, do not invent an empty rebuild.

If a lost host returns, old copies are fenced and retained; the edge closes stale connections.
Inspect fork.detected, recover requested data out of the fenced directory before deleting it,
and reinstate only after resolving which copy is authoritative. If no rebuild happened yet,
`pryx node reinstate <node-id>` restores its assignments. Retire only once placements have moved:
`pryx node retire <node-id>`. Retirement revokes credentials; wipe the host before reuse.

## Certificates and upgrades

Nodes renew automatically before expiry. An expired/lost identity requires an operator token
naming its existing node id, via POST /fleet/v1/tokens with region and node, then the usual join
line. That re-enrolls the same node without discarding its placements. A failed re-enrollment
restores the prior identity where possible; inspect its journal. Replacing a compromised fleet
CA cuts nodes off until each re-enrolls under the new CA; dual CA trust is not implemented.

Deploy the daemon, control, edge and clients from one release. Control serves the signed daemon
release to enrolled nodes; one healthy node per region upgrades at a time. A node keeps pryxd.prev
and rolls back if its new daemon cannot reconcile and get an accepted heartbeat. Regions stop
on a failed rollout. PRYX_UPGRADES=off stops offers. Verify release attestations and SHA256SUMS
as described in README. Never push tags by hand; the release workflow creates them after CI.

## Disk, duplicates, observation and undo

Watch free disk near the configured floor, snapshot/upload failures, multipart uploads left in
the store, certificate expiry, unavailable nodes, duplicate identities, fork.detected and
placement errors. Delete incomplete multipart uploads with a bucket lifecycle rule. Do not drop
local copies whose only store copy is missing. Deleted data stays in daemon trash for its
configured retention; release and destroy are deliberate operations.

A duplicated enrolled disk image becomes quarantined. Find and stop the duplicate, remove its
identity, then `pryx node clear-quarantine <node-id>`. Templates must have an empty machine-id
before first boot. Keep metrics private: pryxd's ops listener, edge's metrics listener and the
operator summary. No event or metric is a reason to declare a host lost by a timer.

Up prints its undo commands. Stop/disable pryx-edge, pryx-control, pryxd, pryx-store and
pryx-postgres; remove their managed unit files and reload systemd. Keep /etc/pryx and Docker
volumes until credentials/backups/data are saved. Removing pryx-postgres and pryx-store volumes
and /var/lib/pryxd destroys data and is always a separate explicit operator action. Docker,
nftables and Docker's daemon.json remain installed; existing Docker settings are merged, and
running containers cause a reload rather than an automatic restart.

## CLI installation and client credentials

The release includes install.sh in SHA256SUMS and the release attestation. The script pins its
release version, verifies the CLI digest before execution, and installs on Linux x86_64.
The README's four commands need no manual exports: after installation, up writes only the public
API URL/key to ~/.config/pryx/client.json (0600, private directory) for the invoking user.
All root operations finish before up drops groups/gid/uid to write that file. PRYX_CONFIG may
select another owned/private client file; an environment API URL never borrows a saved key for
a different endpoint. PRYX_API_KEY explicitly overrides saved credentials.

This public API credential file is the K9 exception to the original environment-file-only rule.
CA, operator and store credentials remain root-only. Up prints the initial key once; repeated up
prints a pryx config key command reference instead. That explicit command reads the user's key
when shell setup is wanted. Up's final output is three export lines followed by the next command.
The bootstrap policy allows official Alpine and Node images; repeat --allow-image to replace it.
